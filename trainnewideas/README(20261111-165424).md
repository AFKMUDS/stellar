# RAP Fresh Training

A clean, fresh training project informed by the RAP work through November 9,
2026. It trains a byte-level recurrent model from your dataset. No old probes,
adapters, experimental outputs, datasets or pretrained checkpoints are bundled.

Start with **START_HERE.md**.

The default model has **6,295,912 parameters**: a 256-dimensional embedding,
512-dimensional carrier, eight learned transition primitives, a bounded
256-slot state cache, and the new reversible byte expression layer. It has no
attention stack.

## Fast start on your laptop

Open your existing **Miniconda Prompt** in this folder so it uses your working
CUDA PyTorch environment.

1. Run SETUP_WINDOWS.bat once. It retains an existing PyTorch installation.
2. Drag your dataset file onto TRAIN_WINDOWS.bat, or put it in data/ and run
   TRAIN_WINDOWS.bat.
3. Run CHAT_WINDOWS.bat after training has saved a checkpoint.

Equivalent first-training command:

```powershell
python train.py --dataset "C:\Programming\Programming_Projects\stellar\ultrachat_train.jsonl"
```

After preparation, an existing cache takes priority when --dataset is omitted.
To switch datasets, pass --dataset and a new --prepared/--run directory.

You can pass a different path. JSONL messages, question/answer pairs,
instruction/output records, JSON arrays and plain text are supported.
Parquet and very large JSON arrays have optional dependencies; see
docs/DATA_FORMATS.md.

On a later session, TRAIN_WINDOWS.bat automatically uses the saved run config
and resumes latest.pt. For the command-line equivalent:

```powershell
python train.py --config runs/rap/config.json --prepared data/prepared --resume auto
```

Use Ctrl+C and wait for saving to finish. The checkpoint includes model,
optimizer, precision scaler, RNG, dataset position, carrier and cache. The
resumed CPU check matched uninterrupted training exactly.

## What is in this version

- The learned float recurrence and coordinate update gate remain the backbone.
- Two ordered retrieval channels preserve inverse-byte and bit-reversal source
  identity. The output head can read both values directly.
- Eight deterministic byte views seed primitive inputs. They do not turn the
  512-dimensional float state into a reversible bit vector.
- A separate causal expression controller predicts through eight reversible
  next-byte code maps. Predictions are decoded to byte probabilities before
  loss or generation.
- All 256 bytes remain valid. Dialogue symbols and EOS live above the byte
  range, so UTF-8 has no reserved-byte collisions.
- Assistant-only response supervision for conversation data; complete text
  supervision for plain text. True response ends get EOS. Truncated records
  are censored.
- Full records flow across training chunks with carrier/cache preserved.
  Gradient history is detached at chunk boundaries.
- Held-out record splitting, exact-content deduplication, disk-backed data,
  periodic validation, samples and milestone checkpoints.
- No forced primitive identities, equal-usage penalty, old boundary adapter,
  online teacher, or hand-written answer lookup.

The default choices are a new experiment, not a claim that the resulting model
already speaks well. The operational checks do not establish language quality.

## Outputs

The default run is runs/rap/. Step counts depend on batch/chunk/accumulation
settings, so they are not directly comparable with an old training script's
step count. The laptop preset presents up to 1,024 input symbols per update
before additional prompt-only prefill chunks; supervised target counts are logged.


| File | Purpose |
|---|---|
| latest.pt | Last completed periodic save or graceful stop |
| best.pt | Best measured validation language loss |
| snapshots/step_XXXXXXX.pt | Milestones every 10,000 updates by default |
| config.json | Fully resolved configuration for correct resume |
| metrics.jsonl | Training losses, learning rate and progress |
| validation.jsonl | Held-out scores and both route families |
| samples.jsonl | Seeded free generations, exact byte hex and EOS status |
| environment.json | Device, precision, parameter count and data fingerprint |

For ordinary sampling:

```powershell
python infer.py --checkpoint runs/rap/latest.pt --prompt "What is gravity?" --max-new-bytes 1024
```

For a persistent conversation:

```powershell
python infer.py --checkpoint runs/rap/latest.pt --chat
```

/reset clears the carrier and memory; /quit exits. Use --temperature 0 for
greedy decoding. For a model trained on plain text, use --raw for completion
without chat symbols.

## Optional task variety

The optional generator supplies fresh copying, reverse-string, order-sensitive
arithmetic, delayed binding, negation/role, XOR and multi-sentence examples.
It does not select routes or supply answers during inference.

```powershell
python make_curriculum.py --out data/skills.jsonl --records 10000
python train.py --dataset "C:\path\main.jsonl" data/skills.jsonl --prepared data/mixed --run runs/mixed
```

The mixture is determined by record counts and lengths. It is not an automatic
quality improvement and is off unless you include the generated file.

To move an already trained **new-format** model to a new dataset or stage:

```powershell
python train.py --dataset "C:\path\next_stage.jsonl" --prepared data/stage2 --run runs/stage2 --initialize-from runs/rap/latest.pt
```

This loads its learned weights and starts a new optimizer, stream, carrier and
cache. Resume is for continuing the same data/protocol; initialization is for
an explicitly new stage. Old B/C checkpoints use different token IDs and
architecture and are rejected.

## Controls and diagnostics

The direct-head config keeps the same new recurrence and memory inputs while
removing the reversible expression controller:

```powershell
python train.py --config configs/direct_head.json --prepared data/prepared --run runs/direct_head
python evaluate.py --checkpoint runs/rap/latest.pt --prepared data/prepared
python diagnose.py --checkpoint runs/rap/latest.pt --prepared data/prepared
```

The default direct model has 6,279,440 parameters, so this is an approximately
parameter-matched **head** control, not a matched GRU or a compute-equivalent
architecture benchmark. Also available at fresh training: --head random;
--retrieval mean, none or random.

Diagnostics distinguish learned transition routing from expression routing.
They report soft weights as well as argmax counts. Shuffling expression gates,
replaying uniform transition weights, and disabling retrieval are frozen-model
interventions, not separate trained baselines. A preferred path is allowed;
route count alone is not a quality verdict.

## Verification and scope

```powershell
python verify.py
```

The checks cover reversible maps, normalized causal predictions, Unicode and
answer masks, document isolation, cross-chunk continuity, bounded memory,
ordered retrieval, disjoint data splits, atomic preparation, exact resume,
new-stage initialization, training, generation and EOS. The included
docs/VERIFIED.json records the local CPU run. CUDA/RTX 4070 speed and peak
memory were not measured here.

configs/smoke.json is intentionally tiny. configs/laptop.json is a conservative
starting preset for your 8 GB laptop GPU; reduce batch_size or chunk_length if
your current environment needs it. configs/cloud.json is a larger CUDA preset.

Installation command reference: [official PyTorch previous versions](https://pytorch.org/get-started/previous-versions/).

The design and research provenance are in docs/DESIGN.md and
docs/DISCOVERY_TO_DESIGN.md. They separate established mechanisms from new
implementation choices and open questions.
